# 高密度打斗(High Density Fight)

> 先导演战斗,再写提示词。绝不以堆叠招式、特效或运镜词代替连续攻防:一组打斗是**一条**因果链——抢空间 → 对真实线路反制 → 接触与位移 → 新高度/角度/破绽 → 追击 → 攻守逆转 → 收束与余波。

## 适用范围(先判定,不适用就不要读下去)

- **适用**:本组 `shots` 里交手镜的 `duration_s` 合计 ≥ 组 `total_duration_s` × 0.6,且属同一场连续战斗(交手双方不变)。交手镜的判定同 fight-choreography:`shot_list.json#poses[].action` 或 `blocking.json` beats 写明出招/格挡/闪避/拳脚/摔投/追击/兵器对撞,双方(或一方与其目标)同镜可见。
- **不适用**:组里只有一两镜零星交手(→ 勾了 `fight-choreography` 就按它逐招写,没勾按「动作写法四条」常规写);对峙、练功、战后余波组;多线混战里找不出一对主交手者的群戏组(先回执说明,由 orchestrator 决定是否回派 shot-planning 拆出主交手线)。
- **与 fight-choreography 的关系**:本技能管**组级结构**(账本、载体路由、阶段接力、密度、收束);fight-choreography 管**逐招措辞**(招式语汇、重量感、表情、「差一寸」)。两者都勾且本组适用时,结构以本技能为准,措辞照 fight-choreography;只勾本技能时,逐招写法按 `references/fight-directing-contract.md` §3 §5 即足够。
- **职责边界**:打什么、谁胜谁负、用什么兵器(剧本 / `poses.action`)、走位与节拍(blocking)、镜数与时长(shot-planning)、机位运镜(camera.json)都是上游事实。本技能只在这些事实之内做**最小补全**的战斗编排;上游没给谁攻谁守、或胜负与站位终点互相矛盾的,回执报缺项,由 orchestrator 回派,不自行编剧情。

## 工作流

动笔前必须读 [打斗导演合同](references/fight-directing-contract.md)(本技能的细则全在里面,本页只是顺序与硬约束)。

1. **建双方资产账本**(合同 §1 §2):每个主交手者一行——外形锚点、身体结构、服装可动部件、战斗目标、兵器种类/数量/尺寸/持握、能力来源与规则、移动条件、本组起点与终点站位、禁止补全项。来源与优先级:用户/剧本明确指定 → 本组 `refs` 参考图清楚可见(角色图锁身份与装备,场景图/背景图锁建筑材质与高低差,白模视频锁站位与动线)→ `bible/props.json`、personality 已确认的战斗习惯 → 保持连续性的最小补全 → 导演原创。道具 `prompt_token` 逐字沿用。**武器与能力零推断**:图里没有、上游没给的不新增;双方资产不串线;无兵器者全程徒手。
2. **载体路由**(合同 §3):为每个主体选与其可见兵器/身体结构/能力介质相符的动作语汇,再按**双方载体差异**设计攻防(长兵对短兵、持械对徒手、人对巨物),禁止把不同载体写成同一套剑法。
3. **选时长结构并映射到 Shot 段**(合同 §5):组 `total_duration_s` ≥ 11s 用五段状态接力,≤ 10s 用四段短结构(不把五段终局硬塞进短组);按镜级 `duration_s` 的累计时间把各阶段分配到既有 `Shot N:` 段——一个阶段可跨多镜,一镜也可承担相邻两个阶段的交界,但**不增删 Shot 段**。用户或上游写明「无蓄力/无停顿/不停/全程连打」时叠加无停顿模式。
4. **三层内部编排**(合同 §4):动作导演定冲突目的、空间主轴、强度曲线、第一次逆转、收束落点;武术指导校验每个关键交换的攻击线、重心、接触、受力;角色行为校验每个选择是否符合目标、体型、性格与**累计受击**。
5. **把编排记入 `grpNNN.json#fight_plan`**(结构见下),**再**写 video_prompt——正文只压缩已经成立的这条时间线,不边写边想招。
6. **写各 Shot 段**:攻防链填在「主体动作与表情」位;每镜开头继承上一镜结尾的位置、朝向、速度方向、高度/支撑面、资产状态、优劣势、环境余波中的至少四项;切镜只改变观察角度,不复位。
7. **静默检查**(合同 §7)全过后交付;任一项失败,回到上游动作重写,不是改措辞。回执登记 skill_report。

## `fight_plan`(写入组级 json,不进 video_prompt 正文)

```json
"fight_plan": {
  "mode": "five_stage | four_stage",
  "no_pause": false,
  "outcome": "上游给定的胜负/收束原文;未定写 open",
  "ledger": [
    { "id": "CHAR-003", "carrier": "长柄武器", "assets": ["平尾红缨枪(prompt_token 原文)"], "forbidden": ["不得新增暗器"], "start": "大厅左侧", "end": "大厅中央" }
  ],
  "stages": [
    { "stage": 1, "role": "即时开战与首次完整攻防", "shots": ["sh014"],
      "chain": "A 蹬地直扎 → B 横格侧闪 → 枪尖擦过斗笠边缘 → B 借后仰贴杆切入",
      "handoff": "B 已贴身、A 枪杆被压在外侧、两人偏向右侧木柱" }
  ],
  "env_hits": ["sh015 栏杆被横削断裂(之后 B 无法再借栏)"],
  "gaps": []
}
```

`handoff` 是交给下一阶段的状态,下一阶段 `chain` 必须从它起笔;`gaps` 记上游缺项(有则回执上报)。

## 关键硬约束

- **开场即威胁**:组首镜直接进入有效攻击或应对;不写对峙、互看、摆姿、空镜、慢速入场——除非上游 `poses.action`/beats 明写本组以对峙开场(那是上游事实,照写,但第一次接触之后本条生效)。需要蓄力时,蓄力发生在移动、逼近、受力、避险之中,战斗不停摆。
- **每个关键交换写满**:`起势/重心 → 加速 → 明确攻击线 → 接触或险些命中 → 合理应对 → 形变/反震 → 沿力线位移 → 环境结果 → 下一动作触发`;同一条攻击线上的连击可共用一组反馈。格挡与落空保留动量并改线;受击后的躯干、脚步、速度、兵器控制**持续影响后续动作**。禁止「完成一招—复位—再起一招」和原地轮流互砍。
- **密度纪律**:每镜关键交换数按镜长——≤2s 一个,2–4s 两个,>4s 至多三个;密度靠「每个动作都触发下一个」,不靠堆招式名。整组至少一次环境结果改变之后的路线、支撑、遮挡或优势;破坏点 ≤3 处且只用场景卡/参考图里真实存在的物件。
- **一镜一运镜不变**:运镜句只写 camera.json 的单一运镜。合同里「镜头由动作触发」在本项目落为**运镜句里写清触发与焦点**(「随他蹬地前冲跟移,焦点落在枪尖与剑身接触点」),不另加第二种运镜;撞击引起的轻微震动写进动作结果,不写成运镜。镜数不够承载阶段时,`gaps` 记「建议回派 shot-planning 拆镜」,不自行加 Shot 段。
- **本技能在适用组内放宽「动作写法四条」②**(低缓优先):允许高爆发连续动作,但该镜其余动态从简,一镜只聚焦一对主交手者;①③④照旧且从严。
- **收束**:上游定了胜负——按五段的三拍终结写(逼出可预判防御 → 利用已改变的重心变线/换轴 → 从真实方向最终命中),写清接触位置、受力方向、败者失去战斗能力的可见状态与落点,胜者沿惯性制动,衣料尘屑余波动到最后一帧;上游未定胜负——最后一帧仍在可读的攻击、闪避、追击、滑行、卸力或环境连锁中,不擅自缴械、跪地、定格摆姿。
- **伤害从上游**:未明定受伤/死亡的,致命招写险过(差一寸、擦过、划破衣料),不写见血、断肢、入体。
- 无飞行能力者只能经跳跃、攀附、坠落、弹射、滑行、受击抛飞或环境借力离地,必有起跳点与落点缓冲。
- 声音只来自可见动作(移动/脚步 → 破风 → 材质接触 → 身体受力 → 环境破坏 → 再加速或落地);cue 文本仍逐字取自 audio_cues/ambience_cues。

## 与团队规范的优先级

- SOUL.md 的结构锚点、主体定义前置、上游逐字片段(风格串/光照/`space_fragment_en`/服装/道具 `prompt_token`/cue/route_en)、冻结 `{}` 台词、Identity lock、宿主写入的固定段(Scene presence / Whitebox reference / Shot plates 等)——**一律不动**;白模参考视频给定的站位与动线是事实,攻防位移不得与之矛盾。
- 与引擎 skill 并用:H3 的六段格式、Seedance 2.5 的【】职责分组、Wan 3.0 五段由各自引擎 skill 负责,本技能只供内容。时间写法随引擎(Seedance 不写秒数,用动作先后承接;H3 可写时间码)。
- 原版 high-density-fight-prompt 里的 `BUNNY` 首词、中文母稿+英文 H3 成对输出、七段导演稿排版**不适用于本项目**:正文结构与语言由 SOUL.md 和引擎 skill 决定,模型触发词若需要应由用户在项目提示词设定里加。
- 风格词归 style.json;负面词只并入 `Global constraints:`,按本组实际风险挑 3–6 条(合同 §6 禁止项)。
